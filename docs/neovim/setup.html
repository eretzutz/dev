A modern, IDE-style Neovim in nine phases

Take this machine from a three-plugin Neovim 0.11 config to a full setup: file, buffer and git panels on the left, a symbol outline on the right, terminals and diagnostics along the bottom, with language servers, formatting, debugging and tests behind them. About an hour and a half by hand, and reversible throughout.

The one decision

Approach

Decision

Build on LazyVim 16 and switch on its extras, rather than growing the hand-rolled config one plugin at a time. You keep three small files of your own.

Why

  • The layout is the hard part, and it is already written. LazyVim’s ui.edgy extra knows how to dock neo-tree, the Snacks terminal, Trouble, Outline and the test panels. Hand-rolling means owning that window-routing glue yourself.
  • There is almost nothing to migrate. The current config is three plugin files. oil and neogit carry over unchanged; the Snacks picker replaces telescope.
  • It is still lazy.nvim. Same lua/plugins/*.lua spec format you already use, and any default can be overridden or disabled from there.
  • It is current. LazyVim 16.0.2 shipped on 8 Nov 2026 and tracks Neovim 0.12.

The trade-off: you inherit LazyVim’s keymaps. Two of your telescope keys change meaning (<leader>fg and <leader>/); Phase 7 deals with them.

The route

Process flow

Nine phases, each ending in a check you can run. Phases 0–3 deliver the layout you asked for, 4–7 add depth, and 8 verifies and commits the result. Ticking steps off below fills in the track.

Phase 0 · 2 min

Snapshot & set aside

Commit the current config exactly as it is, then rename it and its data out of the way. It stays complete and runnable as nvim-legacy, and the new config gets built once, at its final path.

Steps

Make sure no Neovim is running first. From here, NVIM_APPNAME=nvim-legacy nvim starts the old setup.

Exit check

git status in ~/.config/nvim-legacy reports a clean tree, and ~/.config/nvim no longer exists.

Phase 1 · 10 min

Toolchain

Bring Neovim up to the version the plugin ecosystem now targets, install the two missing command-line tools, and fix the broken Node install.

Steps

Prefer Homebrew to own it? nix profile remove neovim && brew install neovim lands on the same 0.12.6.

The pin matters as much as the upgrade. Without a default, proto’s npm and node shims both fall back to Homebrew’s Node, and proto refuses to nest two fallbacks: any npm script that calls node fails in an unpinned directory, which is where Mason installs servers such as json-lsp.

Then set the terminal font to JetBrainsMono Nerd Font in Zed (terminal.font_family) and Warp.

Exit check

nvim --version reports 0.12.x, tree-sitter --version is 0.26.1 or newer, and fd --version and node --version both run.

Heads-up

The legacy config now runs on 0.12 as well, if you start it. Its telescope pin (0.1.5) predates that release and may complain.

Phase 2 · 10 min

Bootstrap LazyVim

With the old setup parked as nvim-legacy, start the new config from the LazyVim starter directly in ~/.config/nvim. Plugins and language tools then install once, at the paths they will keep.

Steps

Run nvim and wait until :Lazy and :Mason show nothing pending. Then quit and reopen once.

Exit check

The dashboard appears, :LazyHealth shows no errors, and pressing Space pops up the which-key menu.

Phase 3 · 15 min · the layout you asked for

Panels

Three extras turn the editor into the layout from the mock. neo-tree supplies the sidebar content, outline.nvim supplies the symbol tree, and edgy.nvim decides which edge every tool window docks to.

Steps

diffview.nvim has had no commits since August 2024. It still works, but treat it as the first suspect if a diff view misbehaves on 0.12.

Out of the box, the git panel and the git pickers look at the directory Neovim was started in. In a folder that holds several repositories and is not one itself, the panel then reports a clean tree and <leader>gs fails. One small module works out which repository has focus, and the git views ask it.

Focus on something that belongs to no repository, such as a terminal or a loose file, leaves the last repository showing. The wiring for the panel and the keys is in git.lua above and in panels.lua in Phase 3.

The git section already had stage, commit and push keys, but nothing on screen said so, and they ran git in the directory Neovim was started in. With the section following the repository in focus, that could commit or push a different repository from the one on screen. This replaces them with versions that act on the repository shown, run in the background, and report what git said.

With the cursor in the git section:

Exit check

A changed line shows a sign, the file appears under <leader>ge, the git section names the repository of the file you are in, gc in that section opens a box for the commit message, and <leader>gg opens lazygit.

The one change from your old spec is default_file_explorer = false. With it on, oil and neo-tree both try to take over when you open a directory.

Neovim has no built-in equivalent of VS Code’s "files.autoSave": "afterDelay", so this adds okuuva/auto-save.nvim and tunes it to behave the same way: the save happens while you are still in insert mode, and at once when you leave the window or Neovim.

Most of the file is about the cases where writing by itself would do harm:

CaseWhat happens
A git commit or rebase message, or anything under .git/Not written. :q! still cancels the commit.
A file named on the command line that lies outside the current directory (kubectl edit, crontab -e)Not written, for the same reason: the calling tool applies whatever is on disk when the editor exits.
Something else rewrote the file while the buffer has edits of its ownAuto-save pauses for that file and says so once. :e! takes the version on disk, :w! keeps yours.
Panels, terminals, read-only files, files with no name, very large filesNever written.
Auto-save switched off with <leader>uWNothing is written, including a save that was already waiting for its delay.
Heads-up

In a project file, :q! no longer throws edits away: they are already on disk. Undo with u instead. Undo history is kept across restarts.

Exit check

A new Lua file indents by four, <leader>fg greps the project, - opens oil on the current file’s directory, and an edit is on disk a second after you stop typing.

Reference

Automation

Phases 1 to 8 are now recipes in the config repo, run with just. The config itself was already declarative (lazy-lock.json pins the plugins, lazyvim.json lists the extras); the recipes cover what was not: installing tools, waiting for parsers and language servers, and checking the result.

A new machine, or a rebuild

The config lives in a private GitHub repo, stnguyenn/nvim-config. On this machine ~/.config/nvim is already a clone of it, so git push after a good update keeps the two in step.

Recipes

RecipeDoesReplaces
just setupdeps, bootstrap, doctor, smoke, in orderPhases 1–8
just depsInstalls the tools in Brewfile, and Neovim 0.12 if it is missing or older. Leaves anything already installed at its version.Phase 1
just bootstrapRestores plugins to the locked commits, then installs parsers, language servers, formatters, linters and debug adapters, and waits until they are donePhases 2–6
just doctorChecks tool versions, plugins against the lockfile, parsers and Mason packages. Exits 1 on any failure.:LazyHealth
just smokeStarts the real editor in a terminal, presses the panel keys, and checks layout, language servers, format-on-save and git signsMost of the acceptance run
just updateUpdates plugins, parsers and tools, then runs doctor and smokeThe update routine below
just rollbackDiscards lockfile changes and puts plugins back to the committed commits:Lazy restore

Every recipe is safe to re-run. The directory name is used as NVIM_APPNAME, so a second clone at ~/.config/nvim-test has its own plugins, tools and state: just bootstrap smoke there tries a change without touching the real setup.

Why it needs scripts

The obvious one-liner, nvim --headless "+Lazy! sync" +qa, quietly leaves a half-built editor. Three things went wrong with it during the setup, and each is now handled:

  • It exits too early. Parsers are still compiling and tools still downloading when Neovim quits. scripts/bootstrap.lua waits for them.
  • Language servers never install. mason-lspconfig skips its automatic install in headless mode, on purpose. The script works out the list from LazyVim’s own configuration and requests them explicitly.
  • There is nothing to test. A headless Neovim has no UI, so the panels and keymaps are never set up. scripts/smoke.lua runs the editor inside another Neovim’s terminal, which gives it a real one.

Not automated: choosing the Nerd Font in terminals other than Ghostty, and your judgement of an update before you commit the lockfile.

Rollback & upkeep

Rolling back

WhenHow
Back to the old setupRun it any time with NVIM_APPNAME=nvim-legacy nvim. To make it the default again, rename the four new nvim directories out of the way and reverse the mv commands from Phase 0.
A bad config changegit log and git checkout in ~/.config/nvim. Every working state is a commit.
A bad plugin update:Lazy restore returns every plugin to the commits in lazy-lock.json. git checkout lazy-lock.json first if the update already rewrote it.

Routine

  • Update deliberately. just update moves plugins, parsers and tools forward and then re-runs the checks; just rollback undoes it. Use the result for a day, then commit lazy-lock.json. By hand, the same thing is <leader>l then U, and :Mason then U.
  • Keep Neovim current first. nvim-treesitter supports only the latest stable release, so run nix profile upgrade neovim before a big plugin update, not after.
  • Read the changelog on major bumps. <leader>L opens LazyVim’s.
